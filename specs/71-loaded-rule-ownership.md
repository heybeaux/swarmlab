# Spec 71 — Loaded rule validation-snapshot ownership (exp65)

## Pre-registration and novelty
Question: does loadPack own the validated rule recipe for the lifetime of its compiled output, or can edits to the original recipe silently change evaluation without another validation/compile? Expected gap: compiled.rule aliases input Rule, so substring pattern, kind, scope, target, severity and enabled can change after load; regex cache can disagree with the changed declaration. A validated policy should not change when a host edits a draft JSON recipe without explicitly loading it again.

## Ownership and scope
Aegis owns independent plain-data Rule values in each loaded CompiledRule (including separate ids sharing input containers and separate loads). Inputs remain editable/unfrozen/unmodified. Explicit reload incorporates source edits in the new output only; explicit compiled.rule edits remain supported and are NOT policed here. Host owns provenance, deliberate compiled edits, authentic policy and exact execution. Scope valid typed plain-data Rule/RulePack incl frozen inputs and optional references; no getters/proxies/functions/cycles/arbitrary extension data, new schema validator, cache-tamper enforcement, await or atomic execution claim. Validation/duplicate/flag/ReDoS behavior must stay compatible.
