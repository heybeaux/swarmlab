## Boundary / proposed contract
For newly minted ProcessInput permits, retain a detached authenticated processTarget and a ProcessInput tool discriminator. Latest ApprovalExecutionSnapshot must supply processTarget with literal verified:true and matching nonblank hostId/sessionId/generationId. Other tools remain compatible without target evidence. Reuse existing snapshot validator for every execution/resume/start entry point; no custom experiment policy. Reject invalid ProcessInput permit creation. Host owns authenticated registry, truthful latest snapshots, durable atomic store and atomic check/use against the actual write. Snapshot-only stale evidence remains a diagnostic negative control, not something Aegis can authenticate. No real host deployment, post-finalization race guarantee, cryptographic attestation, terminal emulation, or old-record upgrade proof. Pre-upgrade records lack a tool discriminator: host must drain old outstanding process permits before adoption; do not pretend legacy records can be inferred safe from hashes.
