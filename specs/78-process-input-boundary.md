## Owner boundary and required contract
Actual host process schema inspected at OpenClaw6a378c2e3a: write uses data/eof; send-keys uses literal/hex/keys; paste uses text/bracketed; submit sends CR regardless of text. Host owns authentication, schema validation, process execution, mutable terminal state and session ownership. Aegis owns faithful classification and binding of the host action; it CANNOT certify the buffered command safe. Project these four actions to ProcessInput; independently require at least ask even empty pack or permissive severity table/predictor. Do not manufacture regex hits; retain any genuine independent deny. Preserve other tool behavior. No command concatenation/decoding, actual shell execution, terminal emulation, automatic safe-fragment exemption, actual approval consumption or calibrated-prediction claim.

Aegis binds action, exact sessionId and all input-bearing raw fields (data,keys,hex,literal,text,bracketed,eof) into a detached metadata digest and both approvalSignature/actionKeyFor; stable equivalent clones yield identical identities. Irrelevant scalar command cannot mask process input. Session/fields must be detached from caller mutation; plain validated JSON only, no proxy/cycle/resource bound claim. No caller-provided safe/approved metadata may waive floor. Input actions intentionally over-review benign/empty writes: a safe-looking byte may complete an earlier command. Read-only list/poll/log plus kill/clear/remove management and legacy exec/read remain compatible. A generic caller can directly use ProcessInput; floor applies even missing metadata. Shadow mode observes ask without blocking and enforcement blocks pending review; no production-plugin rollout claim.
