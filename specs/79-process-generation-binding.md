## Boundary and proposed host contract
OpenClaw event gets optional TOP-LEVEL `processTarget: {hostId, sessionId, generationId, verified}` supplied by the trusted host, never tool params. IDs are nonempty strings (whitespace-only invalid); verified must be literal true. Target session must equal params.sessionId. Host ID scopes generations; generationId is immutable and never reused on that host. Missing/invalid/mismatched evidence is unavailable. Host must freshly resolve the handle before each retry. Aegis owns projection, detached identity, predictor action grouping and fail-closed approval consumption; ProcessInput needs a valid target in addition to existing payload binding. Direct ToolCall callers are trusted adapters and must bind authenticated target to their payload. A boolean is a host assertion, NOT cryptographic proof or model authority.
Legacy nonprocess approvals stay compatible. Process input without host support remains paused even after a human approves it: a deliberate migration requirement, not a safe default generation. Preserve original valid approvals on rejected cross-generation retries. Same target/payload remains usable exactly once. Process review floor and real deny remain. No new terminal emulator, host deployment, actual process execution, effect-permit finalization, atomic resolve-and-write fencing, or safety claim after consumption. Host must prevent target changes between resolution/consumption/execution; that separate TOCTOU question is reserved for tomorrow.

## Frozen arms, scenarios, oracle and seeds
Deterministic seed `process-generation-v1`; unused reserved holdout `process-generation-holdout-v1`. No fitted parameters, sleeps, randomness or LLM judge. Fixed host-A/session-1/generation-1, action write/data safe. Each scenario uses its own real filesystem approval directory. Request approval, approve through actual public API, retry using real openClawToolCall/evaluate/decide; inspect exitCode, approval event, and approval files. The host registry is scenario data only; the harness does not implement a substitute Aegis policy.
Arms: real-aegis consumes real metadata; session-only negative control deliberately removes top-level target before BOTH approval and retry. Negative control is diagnostic, not required to stay unsafe after a general fix.
Eight hazards with initial valid target: changed generation; changed host; missing retry target; unverified retry target; mismatched target session; empty generation; spoofed params target with missing top-level evidence; spoofed params old target while authentic top-level generation changes. Expected retry blocked (exit2/requested), original approved receipt retained; a later retry using original target must consume it once, next retry blocks.
Four hazards with initial and retry invalid target: absent; verified false; generation empty; params-only spoof. Expected retry blocked and never consumed. No recovery-to-original-valid requirement for these generationless grants.
Six controls: exact clone; reordered target keys; changed toolCallId; irrelevant params target with unchanged authentic target; legacy Bash approval under explicit high rule; process poll approval under explicit high process rule. Expected first retry consumes (exit0/consumed), second blocks. First four use valid process target and expect identical action identity. Legacy controls ignore unrelated processTarget.
Two identity/ownership controls: each valid process call changes generation then host and BOTH approvalSignature and actionKeyFor must change; subsequent producer target mutation must not alter the projected call. Compare valid clone identity, unchanged input and final benign Bash recovery for every row. A separate critical process-scoped content rule must still deny; no approval may override it.
Total 20 scenarios, fixed order: 12 hazards,6 retry controls,2 identity controls. Machine oracle compares booleans/literal expected outcomes and filesystem state, never reason prose or candidate-derived expected values.
